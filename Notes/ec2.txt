Issue:Initially, I tried running this environment on t2.micro and t2.medium instances, but they did not work well due to resource constraints. I then upgraded to a c7i-flex.large instance (which provides 4 GiB of RAM). However, even on this larger instance, the available physical memory dropped down to a critically low 173 MiB once the application started.Solution:To give the server breathing room and prevent crashes, I enabled a 4 GB swap file to act as virtual memory.Result:After starting the full Docker microservices stack with swap enabled, the available physical memory stabilized at around 812 MiB (with ~929 MiB safely offloaded to swap). This successfully resolved the memory bottleneck, making the system completely workable and stable.
